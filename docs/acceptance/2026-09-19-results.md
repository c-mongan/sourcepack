# SourcePack 0.3 qualification results

**Decision: continue as a small experimental skill; simplify its interaction overhead before promoting it as a default workflow.** This pass supports reusable acquisition, evidence storage and recovery. It does not show better answers or faster analysis than direct tools.

## What was built

- Timed Summarize extraction with lossless grouped captions and original cue mappings.
- Independent acquisition receipts and usable partial runs when video fails.
- Read/record packets with content integrity and existing lease/citation checks.
- Bounded overview/scene/targeted frames, decoded source timestamps and contact sheets.
- Optional, isolated MarkItDown conversion for local PDF/DOCX/PPTX/XLSX.
- Portable private packs containing answers, source text, original artifacts, visual navigation, observations and gaps.
- A disabled experimental Docling adapter: model completeness is not yet qualified, and OCR is disabled.
- Frozen Agent Skills-style case files, comparison directories, strict grading aggregation and trigger queries.

## Paired answer-quality pilot

The protocol follows [Agent Skills evaluation guidance](https://agentskills.io/skill-creation/evaluating-skills). This is a small development pilot with explicit invocation, not a general benchmark, blind study, adoption test or automatic-trigger test.

Both conditions inherited the same Codex host/model configuration and received the same raw evidence. The exact model identifier and token/cost telemetry were unavailable. Two small tasks shared one fresh context per condition; the unfamiliar video and restart tests used separate fresh contexts. The parent checked selected answers against sources without blinded condition labels.

| Case | Direct tools | SourcePack | Finding |
|---|---:|---:|---|
| Notes: roles, requirements, claim attribution, malicious quoted content, retained evidence | 5/5 selected assertions | 5/5 | Equal |
| Slides: manual review, approved handoff, correct slide locations, honest visual limits | 4/4 | 4/4 | Equal |
| Unfamiliar video: workflow/setup, shown setting, recommendation/outcome distinction, version uncertainty | 4/4 selected questions | 4/4 | Equal; not every sentence independently graded |
| Fresh-context notification-setting follow-up | Correct frame recovered | Correct frame recovered | Both worked; SourcePack initially needed plural search |

The unfamiliar source was Anthropic's [Mastering Claude Code in 30 minutes](https://www.youtube.com/watch?v=6eBSHbLKuN0), 1,687 seconds. Acquisition succeeded with 24 grouped transcript sections, 95 overview frames and eight sheets. Both analyses read all available transcript text and viewed eight sheets; direct tools opened four native frames and SourcePack opened five. The rest were not claimed fully inspected. SourcePack recorded 90 native-frame gaps and 22 structural answer citations.

The checked visual example is `/config` → “Turn on notifications.” It is a slide recommendation, not proof that the option was enabled. The visible `@anthropic-ai/claude-cli@0.2.114` belongs to example npm output and does not establish the running application's version throughout the recording. These distinctions were correct in both answers.

## Time, interventions and cost

| Measurement | Direct tools | SourcePack |
|---|---:|---:|
| Held-out analysis + evidence saving, acquisition excluded | 120.542 s | 447.287 s |
| Fresh-context follow-up | 33.05 s | 41.50 s |
| Reported user interventions | 0 | 0 |
| Tokens / monetary cost | Unknown | Unknown |

SourcePack was about **3.7× slower** on this video trial. It produced a larger standardized pack and recorded 19 inspection packets; direct tools retained a smaller bespoke evidence set. Filesystem latency and tool-call overhead were observed, but their individual causal contributions were not isolated. This is a reason to reduce ceremony, not a speed claim. The two small baseline tasks lacked complete elapsed timers, so no speed comparison is reported for them.

The singular `notification` query initially missed the plural observation. The evaluated agent recovered using `notifications`; the release subsequently gained a labelled prefix fallback. A replay against the same saved run now retrieves the frame with the singular query. The original measured result remains unchanged.

## What remains unproved

- Repeated-run reliability and the full six-case agent-evaluation set. The frozen runner reports unrun cases as pending, never passed.
- Automatic selection accuracy. Twenty positive/negative trigger queries are shipped with train/validation splits, but the 60-invocation sweep has not run.
- General PDF/Office fidelity, complex table reading, layout/OCR, and performance across hosts.
- Lower total cost, better factual reasoning, continuous video understanding or user adoption.

The evaluation snapshot preceded the final recovery/export fixes; those changes have focused regressions and final copied-install smoke verification. Private traces, source bytes and captured frames stay outside Git. Public results contain no user evidence pack.

## Recommendation

Keep the project and the one-skill architecture. Use the structured workflow when repeatable acquisition, inspectable citations or later retrieval matter. Direct tools remain a reasonable choice for a one-off answer. Do not grow a platform or add more orchestrators. The next improvement should reduce inspection/recording steps while preserving explicit image-inspection and citation boundaries; measure it against this saved baseline before claiming a better experience.
